## Orchestration patterns (adopted 2026-08-17 from the paseo evaluation)

Named dispatch shapes for common cross-model collaborations, so A composes a
brief from a template instead of improvising. All are plain `ipc.py` usage — no
new machinery. (Provenance: paseo's `/paseo-handoff` / `/paseo-advisor` /
`/paseo-committee` skills; adapted to the star mailbox.)

- **Handoff (接力: 一家模型出方案, 另一家实现).** A (or one worker) produces a
  PLAN as a file; A reviews/approves it, then dispatches implementation to a
  DIFFERENT role with the plan attached verbatim:
  `send --from A --to D --body-file plan-brief.md --submit-id <key>`.
  The brief must carry the plan file's path AND the guard-safe shell constraints
  (dispatch briefs copy printed values; workers can't read A's history). Use
  when vendors have complementary strengths (e.g. Claude plans, Codex/DeepSeek
  implements) or to keep the planner's context clean for review.
- **Advisor (顾问: 只要第二意见, 不移交工作).** One worker, read-only charter:
  `send --from A --to B --require-watcher "ADVISORY ONLY - do NOT modify any
  file. Question: <decision + the options>. Reply: your recommendation + top
  risks, <=N lines."` A keeps ownership and synthesizes; the advisor's reply is
  input, not a decision (worker rule 3 unchanged). Cheap-tier advisors: wake E
  with `-Model luna` for simple reviews.
- **Committee (合议: 两个立场相反的模型交叉质证).** Same question to TWO roles
  from different vendors, each briefed with an OPPOSING stance ("argue the
  current design is fine" / "argue it must change"), each required to state the
  strongest counter to its own stance. Fan out with `--submit-id`, collect with
  the barrier (`recv --me A --block --count` — mind the 2-rows-per-worker count
  trap), then A reconciles disagreements into the decision. Use for root-cause
  analysis and irreversible calls; two same-vendor panes make a weak committee.

## Dispatch brief standard — seams, sealing, sharing (adopted 2026-08-22)

Three rules distilled from arXiv:2608.16801 (Destefanis & Aste, 1,902
instrumented multi-agent Claude Code runs; the findings are structural — the
specific numbers don't transfer). They extend, not replace, the existing brief
rules (guard-safe constraints verbatim; preprocessed inputs ship as files).

1. **Every cross-worker seam is decided by A, never left to workers to align.**
   Before a dispatch round, A enumerates every interface between batches/roles
   (hash boundaries, entry-pairing口径, naming conventions, sequence handover
   points), rules on each, and writes the ruling verbatim into the brief on
   BOTH sides of the seam. Evidence: a convention straddling two agents'
   boundary failed 10/10 runs even though every run discussed it — talking
   does not close an interface nobody owns.
2. **Verification dispatches land only AFTER the producer delivers.** Agents
   read reachable material unprompted (66% of runs opened another agent's
   prompt; 80% reached for grading files even as decoys). A producer that can
   read the verifier's checklist can drift toward optimizing the checked
   numbers instead of fidelity. So: the audit brief for a verifier role is
   composed and sent only after the producer's deliverable is on disk, and the
   answer side of any audit (counts, hash lists) is generated by the verifier
   at verify time from disk — never pre-shared (existing rule: trust the
   verifier's measured values, not the producer's prose tallies).
3. **Context shared by several workers ships as ONE file, referenced by
   path.** Round spec, controlled vocabulary, gotcha lists go in one shared
   file; each brief carries the path plus only that worker's private part.
   Copying the shared section into each brief is n unicast messages doing one
   broadcast's job.
4. **Every brief states its time budget and the flush rule** (user rule
   2026-08-29). A slices work so the recipient can deliver in ≤15 minutes
   (sized from measured throughput, see capacity section below and memory
   `fleet-worker-capacity`); the brief says so explicitly and requires
   incremental flush (append each finished unit to the deliverable file before
   starting the next — B lost 4 hours of work in 2026-08-29 #1076 by holding it
   all in context). A then runs the 15-minute reply clock from
   `~/.claude/commands/main.md` § A 的职责边界与节奏: no reply at 15 min →
   inspect; working normally → one more 15 min; stalled/abnormal → act now;
   two extensions max. Workers do not self-report quota; the hub clock asks a
   role near the end of its window for a handoff file (operational-cautions.md
   caution 14, 2026-10-21). The flush rule is what protects D, the one role
   without a window, and any role the request reaches too late.
   **Enforced by code since 2026-08-30:** `ipc_dispatch.ps1` refuses a brief
   without a `预算: N 分钟` line (N <= 15), whose header role differs from
   `-Role`, whose `UNITS: n` x measured min/unit exceeds the budget, whose
   absolute paths do not exist, or whose product target is empty; and refuses
   a recipient whose pane reads DEAD/QUOTA/BLOCKED. The reply clock runs inside
   the hub's `watch --me A` (`ipc.py clock` for a Codex hub). Put `预算:` and `UNITS:` on their own lines near the top. The
   `预算:` number comes from `python ~/.claude/ipc/ipc_estimate.py estimate --role
   <r> --brief <file>` (per-model p80 from the timing ledger, 2026-09-19), not
   from a guess; if it prints INSUFFICIENT for the model, keep the 15-minute
   default and slice. The budget also decides whether sibling CLEAN summaries
   wait for this task (`references/command-details.md` § Worker: RESULT-line protocol detail).
   Every brief that names a product file also says how to close: "回复文件首行
   `RESULT: <产物绝对路径>`,有问题或只做了一部分则不写 RESULT 行" (2026-09-19
   RESULT-line protocol, SKILL.md caution 6) — the same absolute path the brief
   declared, so `send`'s disk check and the reply clock's artifact ground truth
   agree on one file.
5. **Every brief carries `完成判据:`** (2026-10-02, book "Build an AI Agent"
   §7.2 / §9.4.2): one checkable line per sub-task, e.g. "12 份全部追加进
   <路径>，每份含来源 URL". The worker self-checks against it before replying;
   A accepts against it on receipt. `ipc_brief_lint.py` check C refuses a brief
   without it. Do not write the closing protocol or today's date into the brief:
   `ipc_dispatch.ps1` appends both (RESULT / UNSOLVABLE / REPLAN, knowledge
   cutoff). On a `[REPLAN]` reply, A fixes the premise and writes a new brief;
   on `[UNSOLVABLE]`, A reroutes or reports — never re-sends the same brief.
6. **Shared view, separate writers, central ruling** (user decision
   2026-10-22, from the AI财务分析 Anthropic case post-mortem: 69 briefs, 17
   review rounds, most bytes were restated background and receipts repeating
   briefs). The mailbox is the doorbell; the content lives in files that every
   role can read and exactly one role writes:
   - **Case brief** (extends rule 3): A writes one file per case holding the
     background every role needs (question and deliverable, outline, units and
     calibers, evidence tiers and source-list path, version boundary, roster,
     change log, and a **已证伪路径** section: the project's `FAIL:` NEW items
     from `ipc.py board --type FAIL`, refreshed before each brief — 2026-10-22,
     from Agensh's typed shared-context board). Briefs cite `见案件简报 §n`
     instead of restating it. What the
     user-level rules require verbatim in every brief (guard-safe constraints,
     preprocessed-input paths, `完成判据:`) stays in the brief.
   - **Read-only board**: A keeps one small status index. Two state axes, never
     merged: execution state copied verbatim from `ipc.py task --id N`
     (QUEUED / IN_PROGRESS / DONE / FAILED / CANCELLED / NEEDS-REVIEW / STALE /
     UNKNOWN; NEEDS-REVIEW and STALE mean "A must act", never "in progress" or
     "failed") and acceptance state from A or the reviewer (`待验收 / 需修改 /
     已接受`). A DONE mailbox task means "replied", not "usable". Task ids are
     stable: re-dispatching the same work to another role changes the current
     message id and owner, never the task id; earlier message ids are history.
     The board holds status lines only; content stays in the task files.
   - **One file, one writer.** Reviewer findings and author dispositions are
     two files that point at each other by stable issue ids (`R<round>-<n>`,
     never renumbered, never table row numbers); A's ruling is a third. Nobody
     prevents overwrites by "editing only my column" of a shared table — two
     file-tool models reading an old version and writing back still clobber.
   - **Version boundary**: drafts are visible but not citable; the version a
     reply names in `RESULT: <path>` is what downstream tasks use. `RESULT:`
     names a path, so an in-place edit silently hands downstream the new
     draft: the submitted file stays untouched while anything depends on it,
     edits go to a new file name (version or timestamp) and a new `RESULT:`;
     if that is impossible, A pauses the affected tasks until the re-submit.
     A change note alone protects nothing. When a shared caliber changes, A logs
     it in the case brief and sends one notice to every affected in-flight task.
   - Roles never dispatch to each other; assignment and cross-role conflicts
     stay with A. No shared-write tables, no file watchers: the existing
     dispatch, wake, reply-correlation, `task --id` and RESULT path are enough.
   Project-level templates (case brief, board, findings/disposition files) live
   with the project; this rule names none. Acceptance of the change is judged
   on outcomes, not bytes: less hub restating and re-entry, less waiting and
   rework, no wrong-version reads or missed acceptance.

## Capacity-aware dispatch (hub A, adopted 2026-08-19)

The IPC layer carries **no context-capacity telemetry** — heartbeats, registry and
`status --watch` prove liveness only. A judges a worker's remaining context by
reading its TUI status line through the fleet mux (verified 2026-08-19 across all
three vendors: claude/kimi/glm panes show `Ctx N% left`, codex shows
`Context N% left`):

```bash
WEZTERM_UNIX_SOCKET=~/.local/share/wezterm/fleet1.sock wezterm cli get-text --pane-id <N> | grep -iE "context|ctx"
```

Role→pane ids: `~/.claude/ipc/wezterm_panes.json`. No match = pane down or
mid-render — recheck once before concluding.

Dispatch policy:

- **Scrape all worker panes before a dispatch round.** Heavy batches (long-doc
  extraction, bulk transcription) go only to workers at **≥70%** or freshly
  cycled. Observed burn rate: E consumes **40–60 percentage points per zsxq
  batch**, so a sub-70% pane cannot absorb one.
- **Below threshold: refresh, don't gamble.** Reset the pane to a known-full
  state (`pwsh ~/.claude/ipc/ipc_newcycle.ps1`, or per-pane /clear +
  /ipc-recover). Success criterion is the status line back at **`Context 100%`**
  — not the absence of output; /clear must be injected via PowerShell (typed
  text can sit unsubmitted in the composer). Resetting to full beats measuring
  precisely.
- **Context % and provider quota are independent axes.** A quota/limit banner
  (D's usual state) is vendor credit exhaustion — leave the role down per the
  restart script's warning; refreshing context does not help, only waiting does.
  Check windows BEFORE the round, not after the banner: `python ~/.claude/ipc/ipc_quota.py`
  (2026-10-17) prints OK / THROTTLE / HOLD per role (5h: 60/80 %, 7d: 70/85 %; A's 5h: 40/60 %
  because the user's own session shares it; C and E share one Codex pair, so a task to one
  spends the other's remainder). THROTTLE = only pieces that fit the remainder; HOLD = nothing
  but an approved exception. A percent has no unit until measured: run `--log` before and
  after a round and read the delta per task type. Windowed roles get a task only when
  predicted duration < time to reset; long, non-idempotent or unbounded work is checkpointed
  to files and goes to the role with the most time left, or to D (the only pay-per-token
  role) in short must-succeed pieces, never as D's whole queue: D's balance has a review-only
  floor and D is the end of the failure chain. B and F (Kimi Code, Zhipu Coding Plan) have
  read their 5h and weekly windows from the vendor usage APIs since 2026-10-21 and get the
  same thresholds; the banner gate stays the last line. Anthropic extra usage
  is OFF on this account, so a 5h hit stops A itself: A's own turns count against the same
  window. (Reviewed with DeepSeek 2026-10-17.) Mid-task, the 5h window crossing 90 % (7d: 98 %) triggers the
  quota handoff (operational-cautions.md caution 14): the role writes its state to a file
  and the rest goes to a role with room.
- **Any refresh discards the worker's task context.** Its session id changes;
  follow-ups need a fresh self-contained `--body-file` brief (workers can never
  read hub history). Corollary of the existing session-echo rule: a reply whose
  `session` ≠ the claimant's means the worker /clear-ed mid-stream — re-brief
  before dispatching a follow-up.
- **Shape batches so cost is predictable**: preprocessed inputs ship as files,
  briefs are self-contained, and batch sizes come from measured saturation
  (e.g. zsxq: 2 calendar days = 4 posts = one saturated batch), not optimism.
