## Hub: flags, JSON outputs, pending states, redeliver

```
ipc.py send --from A --to B "task" --submit-id fx7    # idempotency key: a resend with the same key prints DUP and reuses the row — re-dispatch after a barrier timeout is SAFE
ipc.py send --from A --to B "task" --no-requeue       # fail-closed non-idempotent task: stale lease parks as NEEDS-REVIEW (never auto-requeued/auto-failed)
ipc.py recv --me A --json                             # NDJSON envelopes {id,ts,from,type,task,session,body}: type is the machine-readable outcome (reply|ack|fail), task echoes in_reply_to, session identifies the sender session — reply session ≠ the task claimant's => that worker /clear-ed, its context is gone, re-brief before a follow-up (grok-build envelope + sessionId-echo ideas)
ipc.py recv --me C --json --no-body                   # same envelopes with body "" and body_chars: for signal-only receivers (the Codex supervisor loop) so no body text is parsed as protocol and ids never fall past an output cap; read text with peek --id
ipc.py peek --me A --id 12 15                          # exact rows by id (signals name them; a batch recv can exceed any --tail). An id already trimmed out of `messages` is read from `messages_archive` and printed with `[archived]` (--json: "archived": true), 2026-10-17
ipc.py peek --me C --batch [N] [--json] / --batches    # a complete saved recv --json batch (latest, or number N; envelopes carry "batch"), files <state dir>/_recv_<role>_batch_<N>.jsonl, last 20 per role kept (100 until 2026-10-17); never estimated from truncated output
ipc.py peek --me A --tail 5 --json                     # same, as NDJSON (adds to/unread fields)
ipc.py task --id N [--json]                            # 2026-10-15: one task by id -> {id,state,terminal,from,to,ts,attempts,result,claimed_ts,replies,archived}; state as pending plus DONE/FAILED/CANCELLED; UNKNOWN (exit 1) for a missing id or a non-task row; an archived task answers from `messages_archive` with `[archived]` / "archived": true. Read-only (no reap/archive), so a probe loop never mutates the mailbox; STALE = lease dead and not yet reaped. ipc_dispatch.ps1 confirms a claim with it (IN_PROGRESS or DONE = claimed; FAILED/CANCELLED = stop) because pending omits DONE and a quick finish used to read as "not yet claimed"
ipc.py status --watch B --json                         # 2026-10-15: {role,state,alive,busy,squatter,owner_valid,parked,reason,pid,session,busy_pid,claimed}; exit code as the text form. `parked` = alive AND not busy AND registry owner present; ipc_dispatch.ps1 gates on it via Resolve-IpcDispatchGate (BUSY covers ALIVE+BUSY; REPARK covers DOWN and SQUATTER). The text line's compound states must not be substring-matched (the old gate read ALIVE+BUSY as parked). Offline regression: `uv run ~/.claude/evals/test_ipc_states.py`
ipc.py pending --hub A --json                         # NDJSON {id,to,ts,state,attempts} — state machine-readable (QUEUED|QUEUED-STALLED|IN_PROGRESS|IN-PROGRESS-SILENT|STALE|NEEDS-REVIEW); empty --json output = fan-out complete. QUEUED-STALLED = unclaimed >5min with recipient not busy (#1186 black-hole alarm); IN-PROGRESS-SILENT = claimed but no life-sign (claim/ack/linked reply) >30min (#1188 alarm) — display-only, NEVER auto-requeued; check the pane, or redeliver deliberately
ipc.py redeliver --task N --by A                       # reset a claimed-but-never-started task to QUEUED for a fresh delivery (2026-08-17 #1188) — same row, submit-id/attempts kept, so idempotent re-dispatch stays safe; refused if done/tombstoned; pair with ipc_wake_pane.ps1 if the worker is not parked. This replaces the old undocumented "cancel + new submit-id + manual wake" recovery. attempts is not bumped here; the re-claim bumps it (1 -> 2), so a redelivered task is logged with verdict redispatch
ipc.py archive [--keep 50]                             # 2026-10-17: MOVES handled/terminal rows except the newest N into table `messages_archive` (a failed manual move rolls back and exits 1 with the error on stderr) (same columns + archived_ts, same _ipc.db, one transaction); the automatic trim (past 300 rows, newest 150 kept) moves the same way: INSERT then DELETE of exactly the matching id set, no per-row comparison. Archive key (id, archived_ts): an id archived again (re-created mailbox) is a second version, never a conflict; peek --id / task --id show the newest version (`[archived: newest of N versions, <ts>]` when N > 1; --json adds archived_ts / archived_versions). A failed move rolls back and warns once on stderr, never failing recv/watch/pending. The archive is unbounded and keeps bodies (the durable record for analysis; a manual prune would be a future command)
```

## Worker: RESULT-line protocol detail

```
ipc.py send --from B --to A --in-reply-to N --body-file result.md   # THE result path (2026-09-16): a linked reply closes task N by itself — no separate `done`, no `--type note`. With several open tasks an unlinked reply is REFUSED-LINK (exit 3), never guessed; --in-reply-to naming a task dispatched to someone else is refused too
                                   # RESULT-line protocol (2026-09-19): result.md OPENS with one `RESULT: <absolute path>` line per product file (then any summary). send() checks each path on disk (absolute, exists, mtime >= dispatch) and prints `RESULT CLEAN` / `RESULT UNVERIFIED: <why>` / `RESULT none`. CLEAN => A's watcher (and `recv`) prints one line `DONE #N <- B RESULT: <path>` and A never reads the body. Held only while a sibling task's budget end (dispatch + `预算: N 分钟`, default 15) falls before the flush deadline (oldest held + IPC_HOLD_SECS=900); a long-budget or overdue sibling never delays it. Anything else (a question, partial work, a wrong path) still arrives as `NEW MSG` and A reads it in full — so put a RESULT line ONLY when the product really is on disk
                                   # NEW section (2026-10-17, optional, after the RESULT lines): `NEW:` on its own line, then one `- ` / `* ` / `1. ` item per line; indented lines continue the
                                   # current item; a non-indented non-bullet line ends the section; an inline `NEW: <item>` counts as one item only when no bullet follows it.
                                   # Each item = assertion + consequence of ignoring it, with evidence (operational-cautions caution 6). send() counts the items once into the row and the ledger's
                                   # new_items (lenient, 0 when absent) and prints, after its RESULT line, `ANCHOR #task<N>.<sender>  NEW items=n` (also for a fail reply; `fail` prints the anchor). A CLEAN reply with items reads
                                   # `DONE #N <- B RESULT: <path> (#id) +NEW n: peek --me A --id <id>  anchor #taskN.B` — peek it; a NEW MSG signal carries `NEW n anchor #taskN.B`
                                   # Anchor: every linked reply/fail is stamped `#task<N>.<sender>` (row column `anchor`, ledger `anchor`, recv --json "anchor"/"new_items"); A quotes it in later briefs and conclusions so adoption can be grepped
                                   # Typed items (2026-10-22, from Agensh): an item may open with `FAIL:` / `FACT:` / `OBSERVED:`; the tally rides on every count (`NEW 3 (FAIL 1, FACT 1)`, `+NEW 3 (FAIL 1): peek …`, --json `new_types`); first line > 200 chars prints `NEW-LONG` (warning only)
ipc.py board [--type FAIL,FACT,OBSERVED|all] [--grep kw]... [--since ISO] [--task N] [--json]   # 2026-10-22, hub, read-only: typed NEW items across this mailbox's linked replies (live + archive), one line `#taskN.B  FAIL  <first line>  (#id ts)`; --grep repeats = AND, `a|b` = OR; A runs `board --type FAIL` before writing a brief (case brief 已证伪路径)
```
